## Failed Attempts
- **What was tried**: Initial tab implementation (`39cb823`) used `.gw-tab-panel { display: flex; ... }` as the base rule and relied on the plain `hidden` HTML attribute to hide inactive panels, assuming the browser's native `[hidden] { display: none }` UA stylesheet rule would take precedence. **Why it failed**: CSS specificity tie (class selector `.gw-tab-panel` vs. attribute selector `[hidden]`, both `0,1,0`) resolves in favor of the author stylesheet over the UA stylesheet regardless of declaration order, so `display: flex` always won and every panel rendered at once. This is exactly the bug the user reported after deploying ("all the elements is displayed on one page"). Fixed in `b6eae10` by adding the more-specific `.gw-tab-panel[hidden] { display: none; }` override — not re-attempted differently, this was correctly diagnosed and fixed on the first attempt once the bug report came in.
- No other failed attempts — no errors encountered on the CSS/JS/Jinja sanity checks that were run.

## Context & Gotchas
- **The core bug class to remember**: `[hidden]` attribute selector and a class selector have equal CSS specificity (`0,1,0` each). An author-stylesheet class rule with a `display` property will always beat the UA stylesheet's `[hidden] { display: none }`, regardless of source order. Any future "hide this element" logic in this codebase that uses the plain `hidden` attribute must pair it with an explicit `[hidden] { display: none; }` rule scoped to that class, or use `.classname.is-hidden { display: none; }` toggled via JS instead — don't assume the native attribute alone is enough once the element already has a `display` override.
- **No local `.env`** — only `.env.example` exists in this environment; nothing can be tested against a live Supabase instance or in an actual browser hitting the real backend. All verification this session was static: `node --check` (JS) and a Jinja template parse (Python, invoked as `py`, not `python`/`python3`).
- **`.section` elements with `data-sec="..."` attributes (health, changelog, rgmc, sbic, nav, win, task) are queried globally** by `toggleSection()`, `filterCompact()`, `buildAccessPanel()`, `loadChangelog()`, etc. in `static/script.js` — none of them depend on DOM position/ancestry, which is why reparenting sections into `.gw-tab-panel` wrappers didn't require touching that JS.
